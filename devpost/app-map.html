App map · snapshot of commit 977dd1d

Show Me Once

A take-home guide to where things live. One screen recording becomes a spotlight tour a parent can follow on their own, with each step read aloud.

The main pieces

Helper's browser

Pulls frames from the video (lib/frames/), uploads them, shows review and share.

Next.js routes

The only code with secret keys. Checks the edit key, talks to Supabase and Claude (app/api/guides/).

Claude

Finds each tap and writes the words. Shape guaranteed by the schema, meaning checked by our code (lib/ai/).

Supabase

One guides table and a private bucket of screenshots. Nothing readable from the browser.

Parent's phone

The tour: spotlight, voice, tap the circle (components/tour/).

One action, end to end: “Make my guide”

  1. Frames — extractVideoFrames, isDuplicate, selectFrames
  2. Upload — createDraft, 4 at a time, into the private bucket
  3. Build — buildGuide calls Claude; checkGuide checks meaning; one retry
  4. Review — drag, edit, publish in ReviewEditor
  5. Tour — Tour, Spotlight, speak() on the parent's phone

Code route: three stops (reference route)

Open the project in your editor and search for each anchor.

Stop 1 — which frames get kept. lib/frames/extract.ts → extractVideoFrames samples every 0.5 s; lib/frames/select.ts → isDuplicate and selectFrames decide which frames survive (at most 24).

This is where the Android checkpoint's “only 4 steps” came from: the old comparison dropped a ticked photo as a duplicate. Changing DUP_THRESHOLD changes how many small changes Claude ever sees.

Stop 2 — asking Claude, then checking. lib/ai/buildGuide.ts → buildGuide sends numbered frames with betaZodOutputFormat(AiGuideSchema), so the reply's shape is guaranteed. lib/ai/validate.ts → checkGuide then checks meaning: a frame that exists, a box on the screen, no “click”.

The retry, in short 
// lib/ai/buildGuide.ts (simplified)
const check = checkGuide(parsed, frames.length);
if (!check.hard.length) return ok;          // small slips were fixed and flagged
messages.push({ role: "assistant", content: response.content });
messages.push({ role: "user", content: retryMessage(check.hard) });
// ...one more call, then "Try again" if it still fails (MAX_ATTEMPTS = 2)

Stop 3 — what the parent sees. components/tour/Tour.tsx → goTo moves between steps and calls speak() from lib/speech.ts inside each tap. components/tour/Spotlight.tsx → Spotlight fits the screenshot, dims everything but the target with the spot-ring style, and decides whether a tap hit the circle (onHit) or coaches (onMiss).

A practice to reuse

Let the schema guarantee shape, let your own code check meaning, and retry with the exact errors. The spec recorded this as the open question “if the API already guarantees JSON, what's left for zod and the retry?” (spec.md → Decisions and Open Issues). The answer is in tests/validate.test.ts: replies that are valid JSON but name a frame that doesn't exist, or put a box off the screen, are caught as hard errors. Small slips like “click” or 13 words are fixed and flagged rather than failing the guide.

Before blaming the model, check what it was given. When guides came back with too few steps, the build counted frames at each stage (extracted → kept → steps) before touching the prompt. The steps had been lost in frame dedupe, not by Claude (checklist.md → Revisions). In the three development builds whose logs were checked, each showed attempt: 1, hard: []: the retry was there as a safety net and didn't need to fire.

On another AI project: write the meaning rules as small pure functions with fixture tests, log attempts and errors on real inputs, and trace a bad result back through the pipeline's inputs before rewriting the prompt.
