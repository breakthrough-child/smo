Show Me Once

How it's built: one Next.js app on Vercel, Supabase for private data and screenshots, Claude for the steps.

In plain language

The helper's device does the video work. The browser plays the recording invisibly, grabs a picture every half second, drops look-alikes, and keeps up to 24 — favouring the frames just before the screen changed. The video never leaves the device.

Supabase holds a table and a private bucket. Nothing is readable from the browser directly; only our server code with the secret key can touch it.

Our server routes are the only door. Anything that changes a guide needs the edit key, which the server hashes and compares — the key itself is never stored.

Claude does the thinking. Structured outputs guarantee the JSON shape; our zod checks the meaning; one retry with the exact errors if a hard rule breaks.

The tour is a normal web page. The server signs 1-hour image links; the parent's phone does the spotlight, voice, and buttons — and fetches fresh links if one expires.

Architecture

  • Helper's browser → extracts frames → uploads straight to Supabase with signed tokens; calls our API with the edit key.
  • Next.js on Vercel → the only code with secret keys; checks the hashed edit key; calls Claude.
  • Supabase → guides table (RLS on, no public policies) + private bucket.
  • Claude → frames as base64, structured outputs.
  • Parent's phone → server-rendered tour with 1-hour image links; refreshes them on error.

Your learning goal: the structured-output loop

“Schemas guarantee shape, not correctness.” Lives in lib/ai/; tested in tests/validate.test.ts.

1 · Shapemessages.parse + zodOutputFormat(AiGuideSchema) — the API guarantees the JSON shape. Null parsed_output → hard failure.
2 · MeaningcheckGuide()
Hard: frameIndex out of range, w/h ≤ 0, box fully off-image, empty text.
Soft (auto-fix + flag): clamp box, “click” → “tap”, >12 words → confidence ≤ 0.59.
3 · Retry onceAppend Claude's reply unchanged, then “Your answer broke these rules: …”. Still failing → ai_failed → “Try again”.
4 · SaveSteps, title, sensitive flag saved; unused frames removed. steps: [] → no_steps (no retry — it's a real answer).

Where each piece of data lives
  • Edit key — URL fragment + localStorage smo:key:{id}; only its hash in the DB. Lost both → can't edit (no accounts, accepted).
  • Frames — private bucket until guide deletion; unused ones removed after build.
  • Review edits — memory until Publish / Save changes.
  • Tour progress, share message — memory only.

Failure modes

  • Video won't decode (HEVC/.mov) → “This video won't open…” + Use screenshots instead
  • Black frames on iOS Safari → play/pause priming in the tap; reject near-black frames
  • Claude slow/fails/refuses → “Something went wrong…” + Try again (frames kept)
  • No steps → “I couldn't spot any taps in this one” + tips
  • Expired image links on an open tour → re-fetch
  • No speech → text-only, Hear again hidden

Verify early in the build

  • zodOutputFormat accepts AiGuideSchema
  • fallbacks: "default" works with parse()
  • uploadToSignedUrl with the publishable key, no storage policies
  • iOS Safari extraction gives real (non-black) frames
